## 二、我在验证过程中的三次误判（连同更正）

这一节值得单独写，因为它记录了我对你代码的**三次错误推断**，以及每次是怎么被数据推翻的。你以后读别人的代码也会遇到同样的情况——第一眼觉得有问题的写法，仔细算过之后可能是对的。

**第一次误判：以为 `d2` 存的东西"语义不一致"。**

我看到 `d2 = np.full(N, np.inf)`（未平方的无穷大）和 `distances = norm(...) ** power` 混用，判断"power=2 时 d2 存平方距离，power=1 时存欧氏距离，两者含义不一致"。这个观察本身没错，但我据此推断出"power=1 时 `np.linspace` 的取最小值语义会失效"——**这是错的**。我实测了 power=1 时的概率分布，你的权重和标准写法 `d2 ** 0.5` 完全一致（`np.allclose` 为 True），200 次跑出来的 J 也逐项相同。

原因是你把幂次放在 `d2` 里而不是放在权重里：`d2` 存的是"决定性的那个量"，权重直接用它。只要 power 固定，`d2` 的含义就是自洽的；power 变了，权重跟着变，但"取最小值"这一步始终是在比较同一个量，不会有错。

**第二次误判：以为 `power` 参数有"偏移一位"的语义问题。**

我一度推断你的 `power=1` 等价于标准的 `power=2`（即 D² 抽样），理由是"你的权重是 `norm**power`，标准是 `d2**(power/2)`，所以差一位"。**这同样是错的。** 推导错在把 `norm**power` 直接当成了权重——实际上你的权重是 `d2/d2.sum()`，而 `d2` 已经含了 `power` 次幂，所以净效果就是 `D^power`。标准写法的权重是 `d2 ** (power/2) = D^power`，**两者严格相等**。实测也证实：power=1 时两者的概率分布 `np.allclose` 为 True。

**第三次误判：以为第一个中心没有参与"最近距离"的计算。**

我看到 `distances` 只对 `centroids[i-1]`（最新加入的中心）算距离，判断"第一个中心从没被 `np.minimum` 合并进去，所以 k=3 时 d2 实际上只是'到第 1 或第 2 个中心的距离'"。**还是错的。** 我漏看了 `np.minimum` 是**累积**的：

- `i=1` 时：`d2 = min(inf, dist_to_C0)` = 到第一个中心的距离 ✅
- `i=2` 时：`d2 = min(到 C0 的距离, 到 C1 的距离)` = 到最近中心的距离 ✅

所以第一个中心在第一轮就已经并进去了。我用 20 个随机种子逐个比对初始中心，**没有一次不同**。

三次误判的共同点：我都在"看代码形状"而不是"跑代码验证"。教训是**对可疑写法先构造最小验证，再下结论**——否则很容易把正确的代码判成错的，还会给出错误的修改建议（我前两次都差点给出"修正版"，而那个修正版和你的实现等价，改了等于没改）。

## 三、需要修的 bug：`k=1` 时崩溃

```python
def init_kmeanspp(X, k, rng, power=2.0):
    ...
    for i in range(1, k):          # k=1 时循环体一次都不执行
        ...
    return centroids[:i + 1]       # 这里访问 i，但它从未被创建
```

实测：

```
k=1: UnboundLocalError: cannot access local variable 'i' where it is not associated with a value
k=2: OK, 返回 (2, 2)
k=3: OK, 返回 (3, 2)
```

`k=1` 时 `range(1, 1)` 是空的，循环体不执行，循环变量 `i` 从未被赋值，所以 `return` 那一行直接抛异常。

**修法有两处值得注意。** 第一是补上 `k=1` 的提前返回；第二是把 `i` 的作用域问题一并解决——用 `i` 表示"已选中心数"这种依赖循环变量的写法，在"循环可能一次都不执行"时就会出问题，改成显式计数更稳：

```python
def init_kmeanspp(X, k, rng, power=2.0):
    n = len(X)
    centers = [X[rng.choice(n)]]
    if k == 1:                                   # 提前返回，避免循环变量未定义
        return np.array(centers)
    d2 = np.linalg.norm(X - centers[0], axis=1) ** power
    while len(centers) < k:                      # 用 len(centers) 而不是循环变量
        total = d2.sum()
        if total <= 0:
            break
        centers.append(X[rng.choice(n, p=d2 / total)])
        d2 = np.minimum(d2, np.linalg.norm(X - centers[-1], axis=1) ** power)
    return np.array(centers)
```

改动的另一点是**把 `d2` 的初始化并入第一轮**：原来是 `d2 = np.full(N, np.inf)`，靠第一次 `np.minimum` 把第一个中心"灌"进去。现在直接初始化成到第一个中心的距离，同时去掉 `inf` 和那次多余的 `min` 运算。两种写法结果相同（我验证过），但后者**不依赖"初始值是 inf"这个隐含前提**——如果以后有人调整循环顺序，或者把 `np.minimum` 换成别的逻辑，前者会静默出错，后者不会。

`if total <= 0` 的判断你原来写的是 `if np.all(d2 == 0)`，两者效果一样，但用 `total <= 0` 更直接（除零才是真正要防的事）。

## 四、一处可以简化但不必改

```python
distances = np.linalg.norm(X - centroids[i - 1], axis=1) ** power
```

这里 `np.linalg.norm(..., axis=1) ** 2` 先开方再平方，多算了一次开方。写成

```python
((X - centroids[i-1]) ** 2).sum(axis=1) ** (power / 2)
```

可以省掉开方。不过对这个规模的数据（1500 点、3 个中心、循环 2 次）差别可以忽略，**不值得为此改代码**。提出来只是让你知道有这回事。

顺带一点：`p = d2 / d2.sum()` 里变量名叫 `p`，而它是概率向量不是标量。叫 `probs` 或 `weights` 可读性更好，和 `code/gmm.py` 里 `weights` 的命名习惯也一致。纯命名问题，不影响功能。

## 五、练习 2 的结论怎么答

你的运行结果（我复现过，数字一致）：

| 初始化方法 | 成功率 | 平均 J | 最差 J | 平均迭代 |
|---|---|---|---|---|
| 随机挑 K 个点 | 95% | 4295 | 18069 | 4.4 |
| k-means++ (power=2) | **100%** | **3571** | **3571** | **2.7** |
| 加权但 power=1 | 98% | 3860 | 18069 | 3.6 |

**问题 1（power=2 与 power=1 的差别）**：成功率差 2 个百分点（100% 对 98%），但更值得注意的是**最差 J 的差别**：power=2 在 100 次里一次都没失败（最差就是最优值 3571），而 power=1 最差仍会落到 18069。也就是说 power=1 的 98% 里还残留着那种"差 5 倍"的失败，power=2 把这一类彻底消掉了。

**问题 2（收益体现在成功率还是迭代轮数）**：**两者都有，但对这份数据而言迭代轮数的收益更稳定**。成功率从 95% 提到 100% 看似很大，但要注意基数——随机挑点在 1500 点、3 个分离良好的簇上本来就有 95% 的成功率，提升空间只有 5 个百分点。而迭代轮数从 4.4 降到 2.7（少 39%）是**每一次运行都能省下的**，与运气无关。

这个对比说明一件事：**k-means++ 的价值随数据难度增长**。在讲义 03 第 1.2 节我补了一张更难的数据（90 点、含一个 J=1049.7 的明显局部最优）的对照表，那里 k-means++ 的成功率优势扩大到 12 个百分点（98% 对 86%）。你可以用练习 2 的代码在 90 点数据上重跑一遍，亲眼确认这个趋势。

**问题 3（power 取 2 的理论理由）**：k-means++ 的近似保证是 $E[J]\le 8(\ln K+2)J_{\text{opt}}$，这个界**正是基于 $D^2$ 抽样证明的**。直觉上的理由是：$D^2$ 与"把一个簇拆成两半能省下多少 J"成正比——如果某片区域还没有中心，那里每个点的 $D^2$ 都很大，抽样会强烈倾向于往那里放一个新中心，而新中心带来的 $J$ 下降量恰好也正比于 $D^2$。用 $D$ 而不是 $D^2$ 时，远处点的优势被削弱（距离是别人 2 倍的点只得到 2 倍概率而不是 4 倍），覆盖不均衡，所以理论上界不成立——你的实验里 power=1 最差仍落到 18069，正是这种覆盖不足的表现。

## 六、小结

`init_kmeanspp` 的实现思路和细节都对，特别是"用 `np.minimum` 累积最近距离"和"把幂次放进 `d2`"这两处，是正确且简洁的写法。唯一要修的是 `k=1` 的边界（顺便把 `d2` 的初始化改成直接算第一个中心的距离，去掉对 `inf` 的隐含依赖）。
