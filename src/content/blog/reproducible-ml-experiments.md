把课程实验整理成仓库时，最容易犯的错是把「能跑」当成「可复现」。一个实验仓库至少要做到三件事：结果数值能从脚本重新生成，运行环境写清楚，原始数据与产物体积可控。

第一，报告里的数字不要手抄。让实验脚本把全部指标写到 results.json，再由生成脚本从 JSON 生成 Markdown 报告。这样重跑实验后报告会自动更新，不会出现正文与结果文件对不上的情况。插图同理，都由脚本产出。

第二，数据集和模型权重不要进 Git。MNIST、Fashion-MNIST、动漫头像这类数据动辄几百 MB 到几 GB，权重也会迅速膨胀；仓库里只保留下载脚本、数据说明和最终的 results.json。每个实验目录的 README 写清楚数据从哪来、放到哪个路径、依赖什么版本。

第三，固定随机种子并记录环境。数据划分、初始化、采样都要固定 seed，报告里写清 Python、NumPy、PyTorch 与 CUDA 版本。否则同一份代码在不同机器上会给出不同的小数，复现就变成口头承诺。

最后是隐私与提交范围：公开发布前清掉姓名、学号、本地绝对路径和含个人信息的截图，Office 导出与训练日志不入库。仓库可以公开，但不需要把工作目录一起公开。
